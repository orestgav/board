# Інструкції для AI

Це репозиторій **дошки кампанії**: статичний редактор полотна для D&D-кампаній,
що ведуться в markdown. Сама кампанія живе в окремій теці (окремому git-репо),
а дошка лише відкриває її в браузері. Що вміє дошка й усі поля
`board.config.json` — [README.md](README.md).

Найчастіше тебе просять про одне з двох.

## А. Розгорнути нову кампанію

ДМ хоче завести свою кампанію в цьому форматі. Шаблон —
[campaign-template/](campaign-template/): структура тек, правила для AI
(`ai-context/`), схема метаданих, шаблони карток, валідатор і CI.

### 1. Спитай ДМа

Нічого не вигадуй — спитай і дочекайся відповіді:

- назва кампанії (для інтерфейсу дошки) і короткий `id` латиницею (`my-campaign`);
- де створити теку. Типово — **поруч** із цим репозиторієм, не всередині нього;
- редакція правил (5e 2014 чи 2024) — якщо ДМ хоче, щоб це було в README;
- чи заводити віддалений репозиторій і де. Радь **приватний**: у базі спойлери.

### 2. Скопіюй шаблон

Вміст `campaign-template/` разом із прихованими файлами (`.gitignore`,
`.gitattributes`, `.github/`) — у нову теку:

```powershell
Copy-Item -Recurse campaign-template ..\<тека-кампанії>
```

```bash
cp -r campaign-template ../<тека-кампанії>
```

### 3. Підлаштуй під кампанію

- `board.config.json`: `id` і `name` — з відповідей ДМа. Решту полів не чіпай,
  поки ДМ не попросить: типові значення описані в [README.md](README.md#нова-кампанія).
- `README.md` кампанії: заголовок — назва кампанії.
- Полиць (держав, міст, груп у `world_data/`) у шаблоні навмисно немає — вони
  заводяться з першими картками, за погодженням з ДМом
  (`ai-context/AI_INSTRUCTIONS.md`, п. 2a).
- Лор, NPC, локації, хронологію **не заповнюй**. `ai-context/` лишається з
  «Не визначено», доки ДМ сам не дасть зміст.

### 4. Git

```bash
git init
git lfs install      # картинки в _media/ і board/media/ ідуть через Git LFS
git add -A
git commit -m "Скелет кампанії"
```

Без Git LFS картинки ляжуть у звичайну історію й роздують репозиторій — якщо
`git lfs` нема, скажи ДМу встановити його (https://git-lfs.com).
Віддалений репозиторій і `git push` — лише якщо ДМ на це погодився.

### 5. Перевір

```bash
node tools/validate.mjs
```

Потрібна Node.js 22+. Має бути «Помилок: 0».

### 6. Скажи ДМу, як відкрити дошку

Desktop Chrome або Edge → https://orestgav.github.io/board/ → **«Обрати теку
кампанії»** → нова тека → дозволити читання й запис. Дані не завантажуються
на сервер: браузер пише прямо в локальну теку, а зміни видно в `git status`.

### 7. Необовʼязково: панель «Партія» (D&D Beyond)

Лише якщо ДМ хоче живі листи гравців на дошці:

1. У картку гравця — `ddb_id: <номер>` з адреси `dndbeyond.com/characters/<номер>`.
2. Кожен гравець робить свій лист публічним: *Character Settings → Character
   Privacy → Public*.
3. ДМ розгортає **власний** Cloudflare Worker з [worker/ddb-proxy.js](worker/ddb-proxy.js)
   — покроково в README, розділ «Посередник». Код можна брати без змін:
   адреса `https://orestgav.github.io` уже дозволена.
4. Адресу Worker — у `board.config.json`:
   `"party": { "proxy": "https://<назва>.<акаунт>.workers.dev" }`.

Чужу адресу посередника не підставляй — кожен ДМ використовує свій Worker.

### Обмеження формату

Формат україномовний. Назви секцій (`## На дошці`, `## Звʼязки`) можна
перевизначити в `board.config.json`, але розмір істоти в статблоці дошка
розпізнає лише українськими словами (`Середній`, `Великий`, …) — див.
`ai-context/SCHEMA.md`.

## Б. Змінити код дошки

- Код — у `public/` (браузер), `src/server.mjs` (локальний Node-fallback),
  `worker/` (посередник D&D Beyond). Без збірки й залежностей.
- README — це опис поведінки: змінюєш поведінку — онови README.
- Тести: `npm test` (разом із браузерними, потрібен Chrome) або
  `npm run test:unit`. Workflow Pages публікує сайт лише після зелених тестів.
- Зміни формату карток (поля, секції) треба віддзеркалити в
  `campaign-template/` — інакше нові кампанії розійдуться з дошкою.
