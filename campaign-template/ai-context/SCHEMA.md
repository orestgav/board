# SCHEMA — YAML metadata для сутностей кампанії

Усі файли сутностей починаються з YAML блоку.

## Обов’язкові поля

- `type` (обов’язкове)

## Дозволені поля

- `type` — один з: `player`, `npc`, `location`, `world`, `faction`, `session`, `creature`, `item`, `encounter`, `ai-context`, `board`
- `name` — відображуване ім’я сутності (рядок)
- `status` — стан (для персонажів/істот): `alive` / `dead` / `unknown`
- `location` — посилання або назва поточної локації (бажано `[[...]]`)
- `tags` — масив тегів (рядки)
- `image` — картка-ілюстрація: **тільки імʼя файлу** з `_media/` (напр. `<слаг>.webp`), без шляху
- `initiative_token` — окремий WebP-маркер для статблоку істоти: **тільки імʼя файлу** з `_media/initiative-tokens/`
- `image_known` — чи відомий гравцям вигляд сутності; `false` означає, що портрет гравцям не показують, хоча в приватній картці `image` лишається
- `map` — карта локації: **тільки імʼя файлу** з `_media/maps/`; поле дозволене лише для `type: location`
- `map_data` — імʼя JSON-розмітки районів і обʼєктів із `map-data/`; координати задаються у відсотках від верхнього лівого кута

### Прапорці видимості

- `secret: true`, `public: false` або `pc_known: false` означають, що картка не для гравців: публічної довідки в неї немає, межу знання тримає `## Що знають гравці`.
- `image_known: false` не приховує картку чи довідку, а лише не публікує її поле `image`. За відсутності прапорця портрет вважається відомим.
- Поля необов'язкові. Якщо поле вказане, значення — лише `true` або `false` (можна в лапках).
- Коментар після пробілу дозволено: `secret: true # таємниця`.
- Порожні й помилкові значення та повторні поля — помилка перевірки й збірки.
- Валідатор і генератори використовують `tools/frontmatter.mjs`: плоскі поля `key: value`, без вкладених або багаторядкових YAML-структур. Посилання `[[...]]` і списки тегів зберігаються в наявному форматі.

### Поля для `player`

- `player` — імʼя гравця за столом
- `level`, `class`, `species`
- `ddb_id` — номер листа на D&D Beyond (з адреси `dndbeyond.com/characters/<номер>`). За ним панель «Партія» на дошці тягне живі HP, комірки, ресурси й інвентар

### Поля для `creature`

Статблок зберігається так: **цифри — у YAML**, **дії та риси — звичайним Markdown**. З цього формату дошка малює картку-статблок, тому структуру треба тримати.

YAML: `size`, `kind`, `subtype`, `alignment`, `ac`, `hp`, `speed`, `initiative`, `str`/`dex`/`con`/`int`/`wis`/`cha` (**модифікатори**, не значення), `saves`, `skills`, `senses`, `languages`, `cr`, `xp`, `pb`, `gear`, `source`.

`size` — лише одне з: **Крихітний · Малий · Середній · Великий · Величезний · Гігантський** (завжди в чоловічому роді, незалежно від `kind`; дошка за ним рахує розмір токена). Якщо варіантів два — «Середній або Великий».

Тіло — секції `##` у такому порядку: **Риси · Дії · Бонусні дії · Реакції · Легендарні дії · Закляття**, далі службові **Тактика · Де використовувати · Що знають гравці**.

Кожен пункт — абзац виду `**Назва.** Опис.` Порожнє значення — `—`.

Бестіарій — лише для ДМа, не для публікації. Службові секції картка-статблок не показує — вони доступні в її нотатках ДМа. Прапорці знання гравців на картку не впливають.

### Поля для `item`

- `rarity` — стандартна англійська рідкість з малої літери: `common`, `uncommon`, `rare`, `very rare`, `legendary`, `artifact`. Якщо рідкість не визначена, поле лишається порожнім.
- `attunement` — чи потребує предмет налаштування: **обовʼязкове**, лише `true` або `false`.
- `image_padding` — необовʼязковий, `true`, якщо предмет на арті впритул до країв кадру й на картці дошки виглядає завеликим. Дошка тоді додає картинці відступ.
- `price` — ціна за одиницю, **завжди число (float) у золотих**, без валюти: `280`, `29.9`. Дрібні монети — частки золотого: 1 срібний = `0.1`, 1 мідний = `0.01`. Якщо ціна невідома, поле лишається порожнім.

#### `## На дошці` для предметів

У `## На дошці` **не пишемо рядок типу й рідкості** — `Wondrous Item, Uncommon`, `Ring, Rare (потребує налаштування)`, `Potion, Common` тощо. Рідкість і так видно з кольору стрічки на картці дошки (поле `rarity`), налаштування — з поля `attunement`. Секція одразу починається з опису чи механіки.

#### `## На дошці` для зброї

Стандартний вигляд секції для зброї (і щитів): три блоки, розділені порожнім рядком, без заголовків і без `[[посилань]]`. Текст береться з `## Опис` і `## Механіка` тієї ж картки; ціна й «якісна немагічна» сюди не йдуть — ціна вже в шапці картки.

1. **Опис** — абзаци з `## Опис`.
2. **Механіка** — рядки з `## Механіка` без маркерів списку, по одному в рядку.
3. **Прийом** — текст прийому з назвою жирним на початку, без заголовка `###`. Для звичайної зброї — `**Збройний прийом цвайхандера.**`, для особливої властивості — `**Властивість <зброї>. <Назва>.**`.

```markdown
## На дошці

Цвайхандер — великий двосічний меч. Довге незаточене рикасо відділене від робочої частини клинка малою гардою — «кабанячими іклами». Вони захищають руку, коли боєць перехоплює клинок.

**Військова зброя, ближній бій.**
**Шкода:** 2к6 рубана.
**Властивості:** важка, дворучна.

**Збройний прийом цвайхандера.** Коли ви робите атаку цвайхандером, можете застосувати напівмеч: тримати одну руку на руківʼї, а другу — на рикасо. Ви отримуєте **+2 до кидка атаки**, але в разі влучання завдаєте **на 2 менше шкоди**.
```

### Поля для `encounter`

- `difficulty` — `low` / `moderate` / `high` (бюджет XP за DMG 2024)
- `party_level`, `party_size` — під який склад рахувалося

### Тип `board`

Службові файли нотаток канви лежать лише у `board/notes/`, мають префікс
`map-` і не призначені для гравців. Окремі нотатки розділяються
якорями, які створює редактор:

```markdown
<!-- note n1 -->
Текст нотатки з підтримкою [[внутрішніх-посилань]].
```

Якорі не редагуються вручну й мусять бути унікальними в межах файлу.

## Картинки

Картинки лежать у `_media/`, розкладені за типом сутності:

```
_media/npcs/       портрети NPC
_media/locations/  види локацій
_media/items/      предмети
_media/creatures/  арти істот для статблоків
_media/initiative-tokens/  вузькі маркери ініціативи для друку
_media/maps/       карти світу й локацій (Git LFS)
```

Правила:

- **Формат — тільки WebP** (альфа-канал підтримується). PNG/JPG конвертуються до запису в `_media/`: портрети й арти q82, карти q90.
- **Імʼя файлу = слаг картки**: `<слаг>.webp` для `<слаг>.md`. Кілька картинок — `<слаг>-2.webp`, `<слаг>-<що>.webp`. Спільна сцена — через дефіс: `<слаг-1>-<слаг-2>.webp`.
- Імена мають бути унікальні по всій теці `_media/` — валідатор це перевіряє.
- У YAML — `image: <слаг>.webp` (лише імʼя, без шляху). Це машинне поле: з нього потім тягнутимуться портрети.
- Для локації `map: <слаг>-map.webp` окремо привʼязує карту з `_media/maps/`. `image:` лишається головною ілюстрацією картки і єдиним зображенням, яке показується гравцям.
- Для статблоку ворога `initiative_token: slug-token.webp` привʼязує окремий маркер з `_media/initiative-tokens/`. Формат маркера — 17 × 63 мм, вертикальне кадрування на білому тлі; боки істоти можна трохи обрізати. PDF A4 збирається лише за окремим запитом ДМа з переліком потрібних маркерів; друкувати його у масштабі 100%.
- `map_data: <слаг>-map.json` привʼязує семантичну розмітку з `map-data/`. `areas[].points` містить полігони районів, а `landmarks[]` — точки або прості геометрії обʼєктів. Усі координати мають бути в межах `0–100`.
- У тілі картки — **звичайний Markdown із відносним шляхом**, бо Обсидіана в нас нема, а так картинку видно у прев'ю VS Code і на GitHub:

```markdown
![Назва](../../../_media/npcs/<слаг>.webp)
```

  Кількість `../` рахується від глибини картки: `world_data/npcs/<місце>/<слаг>.md` -> `../../../_media/...`, `world_data/locations/<держава>/<місто>/<слаг>.md` -> `../../../../_media/...`.
- Формат `![[<слаг>.webp]]` **не використовуємо** — він рендериться тільки в Обсидіані.
- Валідатор падає, якщо `image:` чи `map:` вказує на неіснуючий файл, карта лежить не в `_media/maps/` або відносний шлях бʼється.

## Загальні правила

- YAML має бути першим у файлі
- Використовуй kebab-case для назв файлів
- `name` може бути з пробілами; файл — ні
- Якщо `location` — відома локація, використовуй `[[назва-файлу]]`



## Секція «Публічна довідка»

У кожної сутності, яку бачать гравці:

```markdown
## Публічна довідка

Зв’язний текст на 2–5 речень про те, що **герої знають** про цю сутність.
Пишеться для гравців: «герої», а не «вони»; з контекстом, а не телеграфом.
Якщо є сумнів, чи можна показувати факт — його тут немає.
```

Це **єдиний** текст картки, призначений для гравців. Генератора сайту в цьому репозиторії поки немає; валідатор лише попереджає, якщо в картки типу `npc`, `location`, `faction`, `world` чи `item` без прапорців приватності немає цієї секції.
