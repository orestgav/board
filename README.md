# Дошка кампанії

Статичний редактор нескінченного полотна для кампаній D&D 5e, що ведуться
українською в markdown-репозиторії. Код публікується на GitHub Pages, а
розкладка, нотатки й медіа лишаються в локальному clone кампанії. Одна дошка
веде скільки завгодно кампаній однакового формату й перемикається між ними
одним кліком.

## Відкриття кампанії

Відкрити `https://orestgav.github.io/board/` у desktop Chrome або Edge,
натиснути **«Обрати теку кампанії»** і дозволити читання та запис. Сайт не
отримує GitHub-токен і не завантажує вміст кампанії на сервер.

Відкриті кампанії лишаються в списку на екрані вибору: наступного разу досить
клацнути по назві. Останню дошка відкриває сама, поки браузер памʼятає дозвіл.
Кнопка з назвою кампанії в лівому верхньому куті повертає до списку, щоб
перейти до іншої; перед переходом поточна кампанія зберігається. Хрестик біля
кампанії прибирає її зі списку — сама тека лишається на диску.

Позиція полотна й масштаб лінійки в кожної кампанії свої.

Для локальної розробки можна запустити Node fallback — він відкриває одну
кампанію:

```powershell
node canvas.mjs --base ../dnd-campaign
```

Відкрити `http://127.0.0.1:4173`. У цьому режимі редактор автоматично
використовує локальний HTTP API. Розкладка створиться у `board/canvas.json`
після першої зміни.

## Нова кампанія

Кампанія для дошки — це тека з markdown-картками (фронтматер `type: npc`,
`type: location`, … і секції на кшталт `## На дошці`) та файлом
`board.config.json` у корені. Найменший конфіг — одне поле:

```json
{ "boardConfigVersion": 1 }
```

Решта полів необовʼязкові; без них діють значення формату:

| Поле | Типово | Що це |
| --- | --- | --- |
| `id` | назва теки | ключ, під яким браузер памʼятає позицію полотна й масштаб лінійки; переживає перейменування теки |
| `name` | назва теки | назва в інтерфейсі й у списку кампаній |
| `frontmatter` | вбудований парсер | шлях до власного парсера метаданих (модуль з `parseFrontmatter`), якщо в кампанії він є — тоді дошка й валідатор читають картки однаково |
| `layout` | `board/canvas.json` | розкладка полотна |
| `notes.dir` / `prefix` / `type` | `board/notes` / `map-` / `board` | файли нотаток дошки |
| `media.dir` | `board/media` | карти й ілюстрації, кинуті на полотно |
| `media.entityDir` | `_media` | портрети карток (поле `image:` — лише імʼя файла) |
| `media.cacheDir` | `board/cache` | мініатюри; у git не потрібні |
| `entities.types` | `npc, location, faction, item, creature, player, encounter, world` | які картки шукає `Ctrl+K` |
| `entities.skipDirs` | `.git, .github, .obsidian, node_modules, tools, _templates` | теки, куди індекс не заходить |
| `entities.summarySection` | `## На дошці` | секція, яку показує картка на полотні |
| `entities.linksSection` | `## Звʼязки` | секція звʼязків картки |
| `entities.portraitField` | `image` | поле з портретом |
| `entities.locationMembers` | `NPC, Предмети` | рядки секції звʼязків локації, чиї картки кнопка «Локація» кладе всередину |
| `entities.statblockHiddenSections` | `Тактика, Де використовувати, Що знають гравці` | секції статблока, яких не видно на полотні (лише в попапі «i») |
| `travel.hide` | — | id рядків таблиці лінійки, які сховати |
| `travel.extra` | — | свої рядки таблиці лінійки (див. «Відстань») |
| `party.proxy` | — | адреса посередника D&D Beyond; без неї панелі «Партія» немає (див. «Партія») |
| `party.interval` | `15` | як часто, у секундах, оновлювати листи (не менше 5) |
| `party.idField` | `ddb_id` | поле фронтматеру гравця з номером листа |

Помилка в конфігу зупиняє відкриття з назвою поля, наприклад
«board.config.json: notes.prefix має складатися з латинських літер, цифр і
дефісів».

## Керування

- колесо — зум до курсора;
- `Space` + drag або середня кнопка — панорамування;
- клік по рамці — вибір, drag за шапку — переміщення;
- протяжка по порожньому полотну — рамка виділення: бере все, що влізло в неї
  цілком і не заблоковане; `Shift` + протяжка додає до вже вибраного, а
  `Shift` + клік по вузлу додає або прибирає його поодинці;
- перетягування, `Delete`, `Ctrl+L` і стрілки працюють з усім виділенням
  одразу; вміст контейнера їде разом із ним, тому окремо не рахується;
- маркери на кутах — зміна розміру; з `Ctrl` увесь вміст масштабується разом із батьком;
- `F` — нова рамка; кнопка «вписати» у правому верхньому куті показує всі вузли.
- кнопка «Нотатка» на правій панелі — створити нотатку в центрі полотна й одразу редагувати її;
- подвійний клік по тексту нотатки — редагувати; `Ctrl+Enter` — зберегти, `Esc` — скасувати;
- кнопка «жирний» під ручкою нотатки робить вибране жирним, а вже жирне — звичайним;
  у файлі це `**зірочки**`, на дошці — сам жирний текст;
- `Ctrl+K` — знайти картку кампанії за назвою, slug або типом і додати її під курсор;
- кнопки «Локація», «NPC» і «Статблок» — той самий пошук, звужений до одного
  типу; локація приходить разом зі своїми NPC і предметами;
- кнопка «Токен» — той самий пошук по бестіарію й гравцях (`type: player`), але
  на полотно лягає кругла фішка: арт у колі, а без арту — перша літера назви.
  Розмір міняється кутами (коло лишається колом), колір кільця — з палітри на
  20 кольорів у меню правої кнопки; за замовчуванням істоти червоні, а гравці
  зелені;
- кнопка «Музика» кладе на полотно трек із YouTube: у вікні досить лінка;
- кнопка «Відстань» унизу правої панелі — лінійка: ламана по карті й час дороги
  для кожного способу подорожі;
- колесо над великим числом HP статблока міняє здоровʼя, а не зум;
- права кнопка на статблоці додає істоту: у бою з кількома однаковими
  створіннями кожне дістає власний рядок лічильника з назвою;
- кнопка «i» в шапці картки відкриває її повний текст у попапі: посилання там
  клікабельні й показують превʼю, а внизу — хто згадує картку;
- під час відпускання рамка вкладається у найглибший контейнер під її центром;
- `Ctrl+Z` / `Ctrl+Shift+Z` — undo/redo;
- `Ctrl+L` — заблокувати виділене, а на вже заблокованому — розблокувати;
  `Alt+клік` дозволяє вибрати заблокований вузол;
- `Ctrl+]` / `Ctrl+[` — на крок вище або нижче, із `Shift` — у край;
- стрілки рухають виділене на 1 px, `Shift` + стрілки — на 10 px;
- `Delete` видаляє незаблоковані вузли виділення;
- `R` / `Shift+R` — повернути виділені картинки на 45° за годинниковою чи
  проти (те саме є в контекстному меню). Рамка вузла стає межами повернутої
  картинки, центр лишається на місці, а вміст — жетони на карті — обертається
  разом із нею. «Копіювати як картинку» дає файл без повороту;
- `Ctrl+C` / `Ctrl+V` — копіювати виділене й вставити копію серединою під
  курсор; вміст контейнера копіюється разом із ним. Копія лежить у системному
  буфері, тому переживає перехід в іншу вкладку канви;
- «Копіювати як картинку» в контекстному меню кладе в буфер PNG, який можна
  вставити будь-куди: для зображення — сам файл у повному розмірі, для NPC —
  лише портрет, для предмета — цілу картку такою, як її видно на дошці;
- копія нотатки — це нова нотатка у файлі тієї карти, куди її кладуть; поза
  картою нотатка не вставляється, про це каже повідомлення;
- якщо в буфері картинка (скріншот чи копія з іншої сторінки), `Ctrl+V` кладе
  її на полотно так само, як дроп файлу, — з тим самим питанням «карта чи
  ілюстрація»;
- права кнопка по вузлу — меню з копіюванням, блокуванням, довідкою й
  видаленням; по порожньому полотну — саме «Вставити».

Картки індексуються за дозволеними `type` із `board.config.json`; `creature` і
`player` — завжди, бо з них робляться токени. Повний текст
не копіюється в `canvas.json`: там зберігається лише slug картки та її геометрія.
Назва секції, що показується на самій картці, задається в
`entities.summarySection` — зараз це `## На дошці`. Секція звʼязків —
`entities.linksSection` (типово `## Звʼязки`); вид апострофа в заголовку
значення не має.

Вигляд картки залежить від її типу:

- `npc` — власна картка з кнопкою **«NPC»**: арт стоїть у слоті сталого розміру
  й показується цілим, без обрізання, а текст `## На дошці` — завжди праворуч від
  нього, на будь-якому зумі.
- `location` — рамка: сама шапка з назвою, без портрета й без тексту. Кнопка
  **«Локація»** кладе таку рамку на полотно вже з NPC і предметами всередині.
  Список веде сама локація — рядки `- NPC:` і `- Предмети:` у її секції
  `## Звʼязки` (спершу NPC, потім предмети); рядок із уточненням
  (`- NPC (ще):`, `- Предмети (у продажу):`) читається як той самий. Посилання на картки, яких немає в
  індексі (наприклад `players/`, якщо `player` не в `types`), пропускаються —
  про них каже повідомлення.
- `creature` — статблок: під шапкою лічильник HP, нижче та сама розкладка, що
  була на сторінці бестіарію (тип і аліньмент, AC/HP/Speed з ініціативою,
  таблиця характеристик із рятунковими кидками, спорядження й CR, далі дії,
  риси та решта секцій). Нотатки ДМа на картці не показуються — вони є в попапі
  кнопки «i». Додається кнопкою **«Статблок»**.
- решта типів — спільна картка: назва з портретом, а при наближенні ще й текст
  секції. Додається кнопкою **«Картка»**.

Окремо стоїть картка **музики** — єдина, що не приходить із репозиторію.

## Музика

Кнопка **«Музика»** просить лінк на ролік YouTube. Годиться будь-який вигляд —
`watch?v=`, `youtu.be`, `shorts`, `music.youtube.com`, з таймкодом чи
плейлистом: у розкладці лишається один сталий `https://www.youtube.com/watch?v=…`
(плейлист, якщо був, зберігається).

Назву канва питає в самого ютуба (`oembed`) — це єдиний момент, коли вона
ходить у мережу. Якщо ютуб не відповів, назву можна вписати руками; у вікні
вона редагується в будь-якому разі. Далі назва живе в `canvas.json`, тож
картка малюється й без мережі.

Сама картка низька — це рівно шапка: іконка, назва треку й кругла кнопка
«плей» праворуч. Вона відкриває ролик у новій вкладці, дописавши до лінка
`t=…s` і `start=…` замість будь-яких позначок часу: інакше ютуб підхопив би
трек із місця, де його спинили минулого разу. Секунду старту можна задати
необовʼязковим полем у вікні додавання (у `canvas.json` — поле `start`);
порожнє поле означає нуль. Заблокована картка не рухається,
але «плей» на ній працює.

Поточні HP живуть у розкладці, а не в бестіарії: три однакові стражники на
полотні тримають своє здоровʼя окремо. Велике число можна вписати або крутити
колесом (`Shift` — по 10), поле поряд задає, скільки зніме червона кнопка й
скільки додасть зелена, і після удару знову обнуляється. Вище максимуму з картки HP не піднімаються, а вниз
ідуть у мінус — видно, наскільки істоту перебили; щойно лишилося менше за
половину, число червоніє. Зміни йдуть в undo/redo разом із рештою полотна. Довгий статблок гортається
всередині картки, а на краях списку колесо знову зумить полотно.

Одна картка тримає скільки завгодно однакових істот: **«Додати істоту»** в
контекстному меню статблока дає ще один рядок лічильника, повністю здоровий.
Поки істота одна, рядок безіменний — як і був. З другої кожен рядок підписаний:
типово «Істота 1», «Істота 2», а права кнопка на самому рядку дає
**«Перейменувати»** і **«Прибрати»** саме цю істоту. Останній рядок не
прибирається: без нього нема чого рахувати. Замок картки бою не спиняє: на
заблокованому статблоці HP так само крутяться, а істоти перейменовуються —
під замком лишається тільки склад загону, тобто «Додати» і «Прибрати». У `canvas.json` одна істота лишається
полем `hp` вузла, а загін переїжджає в масив `creatures` — по `hp` і, якщо вона
не типова, `name` на кожну.

Іконка вкладки — `public/favicon.svg`: жовтий заокруглений квадрат із чорною
«B», у дусі міро. Публікується разом із рештою `public/`.

Іконки — Google Material Symbols Outlined (Apache 2.0). Шляхи вкопійовані в
`public/icons.js`, тож канва не тягне нічого з мережі.

Кнопка «i» в шапці будь-якої картки відкриває попап із повним Markdown: заголовки,
списки, таблиці та Obsidian-callout (`> [!danger]`) рендеряться, а ілюстрації
тіла картки не показуються — портрет і так стоїть угорі попапа.

`[[Посилання]]` у попапі живі:

- наведення показує превʼю: портрет, назву й `## На дошці` (для статблока —
  AC, HP і CR; без такої секції — початок тексту);
- клік відкриває ту картку в тому ж попапі, а кнопка з назвою попередньої
  вгорі (або `Alt+←` / `Backspace`) повертає назад — як у браузері;
- посилання на картку, якої в кампанії немає, приглушене; на саму себе —
  просто виділене.

Внизу попапа — **«Згадують»**: усі картки, сесії й нотатки дошки, що мають
`[[посилання]]` на цю картку, згруповані за типом, із рядками, де саме
згадано (довгий абзац обрізається навколо згадки). Клік по назві відкриває
джерело; для нотатки — закриває попап і показує її на полотні.

Сесії та інші документи з `type`, якого немає в `entities.types` (наприклад
`session`, `ai-context`), на полотно не кладуться й у `Ctrl+K` не шукаються,
але попап відкриває їх за посиланням і бере з них згадки. Нотатки дошки
(`notes.type`) приходять окремо, разом із полотном.

## Відстань

Кнопка **«Відстань»** стоїть унизу правої панелі окремою групою: вона нічого не
кладе на полотно, а вмикає лінійку.

Перший запуск просить калібрування — два кліки по карті в точках, між якими
рівно **100 миль** (найпростіше взяти масштабну лінійку самої карти). Канва
перераховує це в одиниці полотна на милю й памʼятає в `localStorage` — окремо для
кожної кампанії, тож наступного разу питати вже не буде. Кнопка
**«Перекалібрувати»** в підказці зверху міняє масштаб будь-коли.

Масштаб прив'язаний до координат полотна, а не до самої картинки: якщо карту
розтягнути, стиснути або покласти замість неї іншу, лінійку треба
перекалібрувати.

Далі лівий клік ставить точки маршруту — як прокладання дороги в гугл-мапс.
Після кожної точки попап показує загальну довжину ламаної й час дороги. Хрестик
у попапі стирає маршрут і вимикає лінійку — так само, як повторний клік по самій
кнопці. `Esc` лише стирає прокладене, а другий `Esc` вимикає лінійку.
Поки лінійка ввімкнена, ліва кнопка належить їй: панорамувати можна правою
кнопкою чи `Space`, зум колесом працює як звичайно, а сам маршрут тримається
карти на будь-якому зумі.

Типова таблиця взята з книжок і лежить у `public/travel.js`:

| id | Як | Миль/год | Миль/день |
| --- | --- | --- | --- |
| `foot-slow` | Пішки повільно | 2 | 18 |
| `foot` | Пішки | 3 | 24 |
| `foot-fast` | Пішки швидко | 4 | 30 |
| `mount` | Верхи | 4 | 30 |
| `wagon` | Возом | 3 | 24 |
| `sailing-ship` | Вітрильник | 2 | 48 |
| `longship` | Довгий човен | 3 | 72 |
| `galley` | Галера | 4 | 96 |

Кампанія підлаштовує її в `board.config.json`: `travel.hide` ховає рядки за
id, а `travel.extra` додає свої — з тими самими полями (`id`, `label`,
`milesPerHour`, `milesPerDay`, `hoursPerDay` від 1 до 24, необовʼязковий
`note`). Свій рядок з id книжкового замінює його. Так Crown ходить морем
власним кораблем і ховає книжкові судна:

```json
"travel": {
  "hide": ["sailing-ship", "longship", "galley"],
  "extra": [
    { "id": "rosinant", "label": "Росінант", "milesPerHour": 4, "milesPerDay": 96, "hoursPerDay": 24, "note": "швидкість галери" }
  ]
}
```

Темпи й ефекти — PHB «Travel Pace» (с. 182), швидкості суден — «Waterborne
Vehicles» (с. 119). Власної добової швидкості книжка ні коневі, ні возу не дає:
загін обирає темп як завжди, а кінь додає хіба що галоп удвічі швидше і не
довше години. Тому «Верхи» стоять на швидкому темпі, а «Возом» — на звичайному;
це вибір дошки, і кампанія може його переписати своїм рядком `mount` чи `wagon`.

Добова колонка не виводиться з годинної: у книжці швидкий
темп — це 4 милі за годину, але 30 за день, а не 32. Тому цілі дні лінійка
рахує за добовою колонкою, а залишок — за годинною. День пішого переходу — це
8 годин; кораблі з повною командою йдуть цілодобово, тож їхній добовий шлях —
це швидкість на 24. Важкопрохідна місцевість забирає вдвічі більше часу — про
це нагадує підпис під таблицею.

## Партія

Живі листи гравців з D&D Beyond у лівій панелі, на місці «Шарів» (кнопка з
людьми поруч; відкрита завжди лише одна з двох). Поки панель відкрита, а
вкладка видима, дошка кожні `party.interval` секунд тягне всіх гравців;
закрита панель чи прихована вкладка — жодного запиту.

Картка гравця: коротке імʼя, натхнення ★, AC, смуга HP, комірки (пакт —
фіолетовим), ресурси класу, стани, виснаження, рятунки від смерті на нулі й
завантаженість інвентарю у відсотках від `STR × 15` lb. На смузі тимчасові
хіти йдуть окремим синім відрізком за поточними. Щойно втрачене підсвічується
світлим відрізком, здобуте — зеленуватим; через 15 секунд він згасає.
Клік по картці відкриває попап: характеристики, пасивки, DC, гроші, усі
ресурси (разом із безкоштовними заклинаннями й костями хітів), інвентар за
контейнерами з вагою і заклинання. Відкритий попап оновлюється разом із
панеллю.

Налаштування кампанії:

1. У фронтматер картки гравця — номер листа з адреси
   `dndbeyond.com/characters/<номер>`: `ddb_id: 153354937`.
2. Гравець відкриває лист: *Character Settings → Character Privacy → Public*.
   Приватний лист картка покаже як «Лист приватний».
3. Розгорнути посередника (нижче) і вписати його адресу в `board.config.json`:

```json
"party": { "proxy": "https://crown-ddb.<акаунт>.workers.dev", "interval": 15 }
```

Без `party.proxy` кнопки «Партія» немає.

### Посередник

D&D Beyond не віддає CORS-заголовків, тому браузер сам лист не прочитає.
[worker/ddb-proxy.js](worker/ddb-proxy.js) — Cloudflare Worker, який лише
пересилає `GET /character/<номер>` на неофіційний ендпоінт
`character-service.dndbeyond.com/character/v5/character/<номер>` і додає CORS
для адрес дошки. Нічого не зберігає; приватних листів сервіс не віддає.
Чужі `Origin` отримують 403.

1. [dash.cloudflare.com](https://dash.cloudflare.com) → *Workers & Pages* →
   *Create* → *Create Worker*, назва, наприклад, `crown-ddb` → *Deploy*.
2. *Edit code* — замінити код на вміст `worker/ddb-proxy.js` → *Deploy*.
3. Адреса на кшталт `https://crown-ddb.<акаунт>.workers.dev` — у
   `party.proxy`.

Типово дозволені `https://orestgav.github.io` і локальний fallback
`http://127.0.0.1:4173`. Інші адреси — змінна Worker `ALLOWED_ORIGINS`
(через кому). Безкоштовного плану (100 тис. запитів на добу) із запасом
вистачає: шість гравців раз на 15 секунд — близько півтори тисячі запитів за
годину гри.

Ендпоінт неофіційний і може змінитися. Тоді картки покажуть «D&D Beyond
віддав щось незрозуміле», а не криві цифри. Похідні числа (макс. HP, AC,
комірки, ресурси, вага) рахує [public/ddb.js](public/ddb.js) за тими ж
правилами, що й [ddb-importer](https://github.com/MrPrimate/ddb-importer).
Тести — на знеособленому реальному листі
[test/fixtures/ddb-character.json](test/fixtures/ddb-character.json); нову
фікстуру з листа робить `node test/fixtures/anonymize-ddb.mjs <сирий.json> <фікстура.json>`.

## Нотатки

Нотатка мусить бути всередині карти з `board/media/maps/`. Її текст зберігається
не в розкладці, а блоком зі службовим якорем у
`board/notes/map-<назва-карти>.md`. Внутрішні `[[посилання]]` залишаються
звичайним Markdown і перевіряються інструментами кампанії. При перенесенні
нотатки під іншу карту її блок переноситься до відповідного файла — так само й
для нотаток усередині перенесеної рамки, сцени чи локації; undo/redo
переносить текст разом із геометрією. Видалений контейнер забирає з файлів і
нотатки, що лежали в ньому; undo їх повертає.

## Зображення

PNG, JPEG або WebP можна кинути прямо на полотно. Для всього дропу канва один раз питає тип:

- **карта** — `board/media/maps/`, WebP q90;
- **ілюстрація** — `board/media/locations/`, WebP q82.

PNG/JPEG конвертуються у браузері до запису на диск, а наявний WebP не перекодовується. Імена автоматично робляться унікальними в `board/media/`. Мініатюри до 1200 px зберігаються в `board/cache/`; якщо мініатюри там нема (тека не в git, тож на новому clone вона порожня), канва сама зменшує оригінал і кладе результат туди. Портрети карток показуються мініатюрою до 512 px, зробленою на сесію. Повний файл канва бере лише для картинки, яку видно і яка на екрані вже завбільшки з мініатюру. `_media/` лишається окремою бібліотекою зображень сутностей. Resize зображень зберігає пропорції.

Зміни зберігаються автоматично. Якщо вкладку закривають чи ховають, відкладене
збереження робиться одразу, а поки щось не дописано на диск, браузер перепитує
перед закриттям.

Якщо `canvas.json` тим часом змінив інший процес (AI, `git pull`), канва його не
перезаписує: автозбереження спиняється, і зверху зʼявляється вибір — **«Взяти з
диска»** (перечитати дошку, відкинувши незбережене на ній разом з історією undo)
або **«Перезаписати своїм»** (записати дошку поверх чужої правки).

## Тести

```powershell
npm test          # усе: модулі, сервер і канва в справжньому Chrome
npm run test:unit # без браузера
```

Браузерні тести (`test/e2e/`) піднімають headless Chrome через DevTools
Protocol — без залежностей — і ганяють канву по маленькій тестовій кампанії:
жести, історію, нотатки у файлах, конфлікт, закриття вкладки. Режим теки
(GitHub Pages) перевіряється на Origin Private File System браузера. Chrome
шукається у звичних місцях або за `CHROME_PATH`; без нього ці тести
пропускаються, як і з `CROWN_E2E=0`. Workflow Pages запускає `npm test` перед
кожною публікацією.
