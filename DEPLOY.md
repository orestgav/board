# GitHub Pages

Дошка кампанії публікується як статичний редактор. Сайт не має сервера, GitHub-токена й доступу до репозиторію кампанії.

## Як це працює

1. Відкрити дошку в desktop Chrome або Edge.
2. Натиснути **«Обрати теку кампанії»** (або клацнути кампанію в списку нещодавніх).
3. У системному діалозі вибрати локальний clone кампанії.
4. Підтвердити доступ на читання й запис.

Браузер напряму працює з локальними `board/canvas.json`, `board/media/` та `board/cache/` через File System Access API. Папка кампанії не завантажується на GitHub Pages чи інший сервер.

Handle кожної відкритої теки запамʼятовується локально в IndexedDB, тож кампанії лишаються в списку на екрані вибору. Після перезапуску браузер може попросити підтвердити доступ повторно, але шукати теку заново не потрібно. Кнопка з назвою кампанії в лівому верхньому куті повертає до списку.

Git залишається звичайним локальним workflow: зміни видно в IDE та `git status`, після чого їх можна перевірити й запушити вручну.

## Публікація

Workflow `.github/workflows/pages.yml` публікує теку `public/` після кожного push у `main`.

Workflow сам намагається ввімкнути Pages із джерелом **GitHub Actions**. Якщо політика акаунта це забороняє, у налаштуваннях репозиторію `orestgav/board` треба один раз відкрити **Settings → Pages** і вибрати **Source: GitHub Actions**. Після успішного workflow сайт буде доступний за адресою:

`https://orestgav.github.io/board/`

## Локальний fallback

Node-сервер лишається для розробки та браузерів без прямого файлового режиму:

```powershell
node canvas.mjs --base ../dnd-campaign
```

На `http://127.0.0.1:4173` редактор автоматично використовує локальний HTTP API замість вибору папки.
